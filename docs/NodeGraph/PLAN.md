## 1. 目标与非目标

### 目标
- **节点图即模型**：节点 = 一个几何 / 数值运算；连线 = 数据流；改一个参数，下游自动重算，绘图区实时更新
- **复用现有能力**：曲线就是 MiniCAD 的曲线实体（直线、圆弧、圆、多段线），空间曲线是 `Solid::NurbsCurve`，实体与曲面就是 `ISolidKernel` 的 `BodyPtr`；
  拉伸 / 旋转 / 扫掠 / 布尔 / 圆角都经 `ISolidKernel`，曲线 → 轮廓沿用建模命令的 `SolidToolDetail::ProfileOf / PathOf`
- **与图纸联动**：引用节点读取图纸里选中的曲线，图纸改了节点图跟着重算；结果可"烘焙"成真正的实体（可撤销）
- **平台无关**：核心库在 `src/NodeGraph/`（`MiniCAD::Nodes`），编辑器在 `apps/Common`，桌面版、网页版共用
  （网页版没有实体内核：三维节点报"内核不可用"，其余节点照常工作；网格节点不依赖内核，网页版也能用）
- **随文档保存**：节点图存进 `.mcad` / JSON（`nodeGraph`），每张图纸有自己的参数化定义；
  也可以单独存成节点图文件 `.mcnode`（`Graph::SaveToString` 的 JSON，节点面板“文件”菜单：保存整张图或选中的节点；
  打开时空图直接替换，否则选择插入到已有节点右侧或替换整张图，都可撤销），在不同图纸之间复用
- **一个节点库、三个入口**：添加节点菜单、搜索框、本文第 4 节的节点表都来自同一个注册表与同一张分类顺序表，不重复、不遗漏（第 4.1 节）

### 非目标（第一版）
- 数据树（Grasshopper 的分支路径）：第一版只有**扁平列表 + 最长列表匹配**，另有“交叉引用”节点做笛卡尔积，已能表达阵列、序列驱动的批量建模
- 字段（Blender 的 Field 惰性求值）、蓝图式执行流（白色执行引脚）：本系统是纯数据流
- 脚本节点；多线程并行求值（内核不能并发，后台只有一个工作线程，见第 3.4 节）
- 稳定的拓扑命名（圆角选边按 `Edges()` 编号，运算后编号会变）
- Revit 族的尺寸标注约束与参照平面锁定（需要草图约束求解，见 N12）；族类型目录（type catalog）文件
- 网格布尔、细分曲面（SubD）、T 样条

## 3. 数据模型

### 3.1 值与类型（`Value.h`）

| 类型 | C++ | 说明 |
|---|---|---|
| `Number` | `double` | |
| `Integer` | `int64_t` | 与 `Number` 互转（四舍五入） |
| `Boolean` | `bool` | 数值非 0 为真 |
| `Text` | `std::string` | 任何值都能转成文字（面板节点显示用） |
| `Vector` | `Math::Vec3` | 点与向量不区分（同 Grasshopper 的 Point / Vector 互转） |
| `Domain` ✅ | `{double Min, Max}` | 区间（参数曲面、曲线 / 曲面的参数范围、重映射）。数值转区间为 `[0, x]` |
| `Plane` ✅ | 原点 + 单位 X / Y 轴（Z = X × Y） | 工作平面（Revit 的工作平面 / 参照平面，Grasshopper 的 Plane）。平面转 `Vector` 取原点；`Vector` 转平面为过该点的 XY 平面 |
| `Curve` | `shared_ptr<const Entity>` | MiniCAD 的曲线实体（ID 为 0，不在场景里），不可变 |
| `Curve3D` | `shared_ptr<const Solid::NurbsCurve>` | 空间 NURBS 曲线（“空间曲线”），不可变。曲线实体连到 `Curve3D` 端口时自动转换：直线、全是直线段的多段线（可以是空间折线）→ 一次曲线，圆弧、圆、带圆弧段的水平多段线、矩形 → 二次有理曲线（精确），带控制点的样条原样；反过来不能转换 |
| `Body` | `BodyValue { Solid::BodyPtr; bool Void; }` | 内核实体或开放曲面（`ISolidKernel::IsSolid` 区分），不可变；端口上显示为“实体 / 曲面”。`Void` 🆕 为空心标记（第 5 节），变换、阵列、列表节点原样传递 |
| `Mesh` ✅ | `shared_ptr<const Solid::Mesh>` | 三角网格（顶点共用、顶点法线、索引；`Solid::Mesh` 也用于离散），不可变。`Body` 连到 `Mesh` 端口时按默认精度自动网格化；反过来不能自动转换（要经“网格转实体”节点） |
| `Geometry` | — | 只用于端口：接受 `Vector` / `Plane` / `Curve` / `Curve3D` / `Body` / `Mesh`（变换、阵列节点） |
| `Any` | — | 只用于端口：接受任何值（列表节点、面板） |

端口之间能否连线由类型级的 `CanConvert(from, to)` 决定；求值时逐项 `Convert`，失败则节点报错。

**`Body` 端口的子类型提示**（🆕 N5）：`PortSpec` 增加 `BodyKind Kind = Any | Solid | Surface`。它不限制连线（实体与曲面都是 `Body`，
只有求值时才知道），只用于：① 搜索框排序（第 9.2 节，从“加厚”的“曲面”输入拖出时，曲面节点排在实体节点前面）；② 悬停提示
（“曲面（开放）”）；③ 输入不符时的统一报错文字（“只适用于封闭实体：第 n 项是开放曲面（可先“加厚”或“封口”）”）。

### 3.2 列表与最长列表匹配

每个输出端口产生一个列表 `DataList = vector<Value>`。输入端口有两种访问方式：
- **Item**（默认）：节点按项求值。迭代次数 = 各 Item 输入列表长度的最大值，短的列表重复最后一项（Grasshopper 的 Longest List）
- **List**：整个列表一次交给节点（合并、列表项、布尔并集等）

一个输入可以接多条连线，按连线顺序拼接（同 Grasshopper；编辑器里拖到已连接的输入上是替换，按住 Shift 是追加）。
没有连线时用端口上的**内联值**（编辑器里直接改），可选端口没有内联值时为空列表。

### 3.3 节点类型（`NodeType.h`）

`NodeTypeInfo`：ID（如 `solid.box`，存档用，不能改）、显示名、分类（可写成 `大类/小类`，如 `实体/创建`，添加节点菜单分两级，标题栏颜色先按完整分类、再按大类取）、说明、输入端口、输出端口、**参数**（不是端口的设置，
如滑块的最小 / 最大值、布尔运算的种类，编辑器里画在节点卡片上）、求值函数 `Solve(SolveArgs&)`，以及标志
（`DependsOnScene`：读取图纸，图纸几何版本变化时重算）。

新增字段（🆕 N5）：
- `Keywords`：搜索用的别名，空格分开，可中英混写（如 `solid.sweep` 的 `扫掠 sweep 放样`、`surface.loft` 的 `loft 蒙皮 skin`）。
  用来消除 Revit 与 Grasshopper 的叫法冲突（第 4.3 节）
- `Group`：同一小类里的分组号，菜单在组之间画分隔线（如“实体/创建”里形体与基本体之间）
- 显示名、分类可以改（存档只认 ID）；ID 一经发布不再改，节点改名或换分类时在 `Keywords` 里留下旧名，老用户照样搜得到

`SolveArgs`：取当前项的输入（已转换为端口类型）、整个列表、参数；写输出项；报告警告 / 错误；访问求值上下文
（实体内核、场景）。求值函数抛出的异常被捕获并作为节点错误。

**节点类型升级**：给已有节点增加输入端口时（如“拉伸”增加“起点”“工作平面”），新端口放在末尾、带内联默认值，默认值使结果与旧版相同；
读入旧图时端口与参数按**下标**对应（`Graph::Deserialize`）：缺少的取默认值，所以端口可以改名、新端口只能加在末尾。这样 N7 对已有实体节点的升级不需要改 ID。

### 3.4 图与调度（`Graph`）

- 节点 ID、连线（源节点 / 端口 → 目标节点 / 端口）；连线时检查类型兼容与**环**（不允许形成环）
- **脏标记**：改内联值、参数、连线、增删节点时标记该节点为脏，并沿下游传播
- **求值**：Kahn 拓扑排序，只重算脏节点；节点出错时输出为空，下游提示缺少输入；记录每个节点的状态（正常 / 警告 / 错误）、
  消息、耗时（毫秒）、求值次数（测试用）。宿主每帧调用（`MainFrame::SyncNodeGraph`），编辑后的下一帧求值并刷新预览
- **依赖图纸的节点**：上下文里的场景几何版本变了就标脏
- **后台求值（N11）**：桌面版（`AppPlatform::HasBackgroundThread`）不在界面线程上求值，拖滑块不卡界面：
  - `Graph::PrepareBackground`（界面线程）计算命名参数、先算依赖图纸的节点（它们读场景，没有输入端口），再复制出副本：
    脏节点、全部参数与连线，干净节点只在连到脏节点时复制输出；值不可变（曲线、实体共享），复制很便宜
  - 副本交给单个工作线程 `Evaluate`（`SolveContext` 不带场景）；`MainFrame::SyncNodeGraph` 每帧检查，完成后 `MergeEvaluated` 合并回来
  - **脏戳**：每次标脏给节点一个新的 `Stamp()`。只合并本图里仍为脏、脏戳与副本相同的节点——求值期间被改动的节点（及其下游）丢弃结果，
    已算完且没变的上游照样合并，下一轮只算剩下的
  - **轻的仍同步算**：脏节点上次耗时之和（`Graph::EstimatedMillis`）已知且不超过 40 ms（`MainFrame::m_nodeSyncBudget`）时在界面线程上当帧算完，
    与 N11 之前一样没有线程切换和一帧的延迟；用 `SolveContext::Deadline`（预算的 2 倍）兜底，没算完的和重的一起交给后台。
    从没算过的节点（刚添加、刚打开、撤销后）耗时未知，直接交给后台，避免一次长时间卡住
  - **拖动时看中间结果**：正在算的节点被改动时不立刻取消，让它算完；过时的结果先拿来显示（节点仍为脏，`MergeEvaluated`），
    接着按最新的值重算。过时的求值已经算了 1.5 秒以上才取消。进度重绘最多每 100 ms 一次
  - **取消**：`SolveContext::Cancel`，`Evaluate` 在节点之间、节点的各项之间检查（耗时节点可在自己的循环里查 `SolveArgs::Cancelled`），
    被打断的节点保持为脏；单个内核调用不能打断。换了文档、过时的求值算了太久时自动取消；
    工具行的“停止”按钮由用户取消，之后到节点图再被标脏（`DirtyVersion`）或图纸改动前不再自动求值
  - 进度：工具行显示“求值中… 已算 / 共几个节点”，脏节点的卡片显示“计算中…”；烘焙、参数表先停下后台求值（合并已算完的）再同步算完
  - 内核：SMLib 的每个调用与实体析构持有同一把进程级递归锁（`SMLibKernel.cpp`），界面线程（预览离散、建模命令）与工作线程轮流使用；
    界面线程碰上正在进行的内核调用时等它结束（预览在合并后、下一次派发前刷新，避开大部分等待）
  - 网页版没有线程，仍在界面线程上同步求值
- **读写**：经 `ISerializer`，`.mcad` 与 JSON 都适用；未知节点类型读入时保留为"缺失"节点（不丢数据、报错）

### 3.5 预览与烘焙（`Preview`）

- 预览：开着预览的节点里，**没有连到下游的几何输出**（叶子）+ **当前选中节点**的全部几何输出（高亮色）
- 预览几何是不在场景里的实体：曲线直接用，点 → `PointEntity`，内核实体 → `Solid3DEntity`（按 `BodyPtr` 缓存，
  滑块拖动时没变的实体不重新离散）
- 绘图区：`Editor::SetPreviewEntities` → 线进轮廓线流（三维视图里按深度测试），实体的面进着色流，三维视图的深度范围包含预览
- 烘焙：把预览几何复制成文档实体（当前图层），经 `BatchAddCommand` 一步撤销
- ✅ 空心（`Value::Void`）：预览画成橙色线框（实体的各条边，按 `BodyPtr` 缓存；不着色、不写深度），选中时加亮；**不烘焙**
  （`Bake` 跳过并经 `skippedVoids` 返回个数，命令行提示“跳过 n 个空心”），与 Revit 族里空心只用来切除的语义一致
- ✅ 网格：预览为 `MeshEntity`（着色 + 全部网格边，按网格缓存，不需要内核）；烘焙为 `MeshEntity`，导出 DWG / DXF 为多面网格（见第 8 节）
- ✅ 平面：预览画成以原点为中心、边长 10 的方框 + 三色轴（X 红、Y 绿、Z 蓝），不烘焙

### 3.6 撤销（`GraphHistory`）

节点图的编辑与图纸的撤销栈分开：每次编辑前存一份图的快照（JSON 文本），编辑器里 Ctrl+Z / Ctrl+Y 撤销 / 重做。
滑块拖动只在按下时存一次快照。

## 4. 节点库

### 4.1 分类与排序原则

**一张顺序表**：`NodeRegistry` 增加分类顺序表 `CategoryOrder()`（大类与小类的固定顺序，写在 `NodeType.cpp`），
添加节点菜单、搜索框里的分类显示与无关键词时的列表、标题栏颜色都按它；同一小类里按注册顺序（注册顺序即本节表格的顺序），`Group` 不同处画分隔线。
`NodeGraphTests` 检查：每个节点的分类都在顺序表里、顺序表里每个小类至少有一个节点、ID 不重复、同一小类里显示名不重复——
这样菜单、搜索、节点库不会出现“只在搜索里有”或“菜单里有空子菜单”的情况。
`NodeGraphTests --dump-nodes` 按顺序表输出 Markdown 节点清单（名称、ID、分类、端口），用来核对本节表格。

**大类顺序**：从数据到几何、从低维到高维，最后是作用于所有几何的变换：

```
输入 → 图纸 → 数学 → 列表 → 向量 → 曲线 → 曲面 → 实体 → 网格 → 变换 → 组
（参数源）     （数据处理）    （点、平面）（一维）  （二维）  （三维） （离散表示）（通用）（本文档的组）
```

- 曲线 → 曲面 → 实体：建模时先画轮廓、再生成面或体，下游节点在菜单里也在下方
- 网格放在实体之后：网格多由曲面 / 实体转换而来
- **小类顺序**统一为：创建 → (空心) → 运算 → 修改 → 分析 / 转换；即先“有东西”，再“组合它”，再“改它”，最后“读它”
- **一个节点只放一处**。跨类型的节点按以下规则归属：
  - 产生某类几何的节点放在**结果**的大类（挤出曲面 → 曲面/创建；网格化 → 网格/转换）
  - 实体 ↔ 曲面的转换放在“曲面/修改”（拼接、封口、炸开、加厚：曲面是两者的中间状态）
  - 与网格有关的转换（两个方向）都放在“网格/转换”
  - 求交按维数较高的一方放：曲线 × 曲线 → 曲线/分析；曲线 × 曲面、曲面 × 曲面 → 曲面/分析；实体 × 平面 → 实体/分析（截面）
  - 布尔运算放“实体/运算”（输入是开放曲面时报错并提示先加厚 / 封口；曲面的切割用“曲面/修改”的修剪、分割）

**标题栏颜色**：按大类：输入灰、图纸青、数学 / 列表蓝灰、向量绿、曲线黄绿、曲面紫红、实体蓝、网格橙、变换棕；“实体/空心”单独用橙红（与空心预览色一致）；组紫色。

### 4.3 命名冲突

Revit 与 Grasshopper 的中文叫法有冲突，按以下约定区分（关键词保证两种叫法都搜得到）：

| 叫法 | Revit 含义 | Grasshopper 含义 | 本库 |
|---|---|---|---|
| 放样 | 轮廓沿路径扫过（Sweep） | 多截面蒙皮（Loft） | 实体“放样”= Sweep（`solid.sweep`）；曲面“放样曲面”= Loft（`surface.loft`） |
| 融合 | 两个轮廓之间过渡（Blend） | — | 实体“融合”（`solid.blend`）；曲面没有“融合”，同样的几何用“放样曲面” |
| 拉伸 / 挤出 | 拉伸（Extrusion，封闭实体） | Extrude（曲线 → 开放曲面） | 实体“拉伸”；曲面“挤出曲面” |
| 旋转 | 旋转（Revolve） | Revolve | 实体“旋转”；曲面“旋转曲面” |

### 4.4 实现注意（已有节点）

注意：MiniCAD 多段线的凸度正值为**顺时针**（与 `SolidToolDetail::KernelBulge` 一致，交给内核前取反），
曲线节点生成逆时针圆弧时取负值（如圆角矩形）；`NodeSolidTests` 用圆角矩形拉伸后的体积验证方向。
曲线实体 → `Curve3D` 的转换经 `SolidToolDetail::PathOf`（凸度已取反）再 `NurbsCurve::FromSegments`，方向同样正确。

曲面（`BuiltinSurfaceNodes.cpp`）：
- 曲面输出仍是 `Body` 类型（开放的 `BodyPtr`），所以变换、阵列、预览、烘焙、水平截面都直接可用；“加厚”“管道”得到实体，可以再做布尔
- 对开放曲面无意义的操作给出明确提示：“实体信息”输出体积 0 并警告；并集 / 差集 / 交集报错“只适用于封闭实体：第 n 项是开放曲面（可先“加厚”）”；
  “加厚”“偏移曲面”的输入已是实体时报错
- 预览：曲面与实体一样着色（双面光照）；空间曲线显示为带控制点的样条（`SplineEntity`），烘焙后也是样条（`.mcad` / JSON 保存控制点；DWG / DXF 导出暂时跳过样条）。
  曲面烘焙为 `Solid3DEntity`，导出 DWG / DXF 为多面网格
- 网页版：控制点曲线、曲线取点与变换照常（`NurbsCurve` 不依赖内核），其余报“内核不可用”
- 端口颜色：空间曲线为黄色，大类“曲面”标题栏为紫红色，“曲线/NURBS”沿用“曲线”的颜色（`NodeEditor.cpp` 的 `TypeColor` / `CategoryColor`）
- 测试：`NodeSolidTests` 的 `TestCurve3D`（插值、取点、螺旋线 → 管道体积、圆转 NURBS 的长度、端口类型、没有内核时）、`TestSurfaceNodes`
  （放样面积、实体信息的警告、加厚体积与方向、开放曲面布尔报错、旋转曲面面积、点阵曲面面积与加厚体积、曲面取点、直纹面与偏移）、
  `TestSurfacePreviewBakeAndFiles`（预览与着色、烘焙、`.mcad` / JSON 往返后曲面仍是开放的且面积不变、节点图重新求值、DWG / DXF 多面网格、撤销）

### 4.5 曲线修改（N6b）

实现在 `BuiltinCurveModifyNodes.cpp`，算法在 `CurveOps.h/.cpp`（不依赖内核，网页版也能用）：
- **两条路线**：曲线端口是 `Geometry`（曲线实体或空间曲线）。默认挤出方向、各点同高的直线 / 圆弧 / 圆 / 多段线转成多段线（`CurveOps::FlatPolyline`，圆为两段半圆弧），
  用 `PolylineOps`（偏移命令、修剪命令的同一套代码）计算，结果经 `CurveOps::FromPolyline` 还原：相邻同圆圆弧先合并，一段直线 → 直线、一段逆时针圆弧 → 圆弧、
  逆时针整圆 → 圆，其余为多段线，并沿用输入的图层、颜色。所以矩形偏移、倒圆角后仍能作为拉伸的轮廓。其余（空间曲线、斜放 / 竖直的直线等）按 `NurbsCurve` 计算
- **参数 t** 一律按转换后的空间曲线（同“曲线取点”“曲线最近点”“曲线求交”）：曲线实体先求出该处的点，再投影到多段线上，所以 t 在各节点之间含义一致
- **偏移**：开放曲线正值偏向前进方向左侧（从平面法向正向看），闭合曲线正值向外；空间曲线须在一个平面上，变换到平面坐标系后经 `ISolidKernel::OffsetCurve`
  （`SmBSplineCurve::CreateSimpleOffset`），所以没有内核时只能偏移水平面内的曲线实体
- **曲线圆角**：只处理直线段之间的拐角（多段线含圆弧段时报错），圆弧占用的长度超过相邻边可用长度（另一端也有圆角时为一半）的拐角保持尖角并警告；
  空间折线得到二次有理曲线（圆弧精确）
- **分割 / 子曲线**：空间曲线用节点插入（Boehm）在参数处断开，闭合曲线绕过接缝时首尾两段直接连接；分割点在接缝上时不绕
- **延伸**：“自然”方式下直线段沿直线、圆弧段沿圆弧（超过整圈报错）、空间曲线把端部的贝塞尔段在参数 > 1 处外推（曲率连续），长度用二分法对准；“直线”方式接切线段
- **连接**：按容差贪心连链（自动反向），全是同高的曲线实体时得到多段线；空间曲线同阶（或其中一条是一次曲线，先精确升阶）时直接拼接节点矢量，
  两条都高于一次且阶数不同时经 `ISolidKernel::JoinCurves`（`DegreeElevate` + `CreateByJoining`）
- **炸开**：多段线拆成直线与逆时针圆弧（同炸开命令）；空间曲线在节点重复度 ≥ 阶数、且两侧切线方向或曲率不同处拆开（直线与圆弧的接点拆、椭圆的四段之间不拆），
  一次曲线的每段输出为直线
- **投影**：到平面是沿方向的仿射投影（变换控制点，精确）；水平面上的竖直投影保持曲线实体；到实体 / 曲面经 `ISolidKernel::ProjectCurve`（`SmApiProjectCurve`）
- **重建**：两端点固定、均匀节点、弦长参数的最小二乘逼近，输出采样点处的最大偏差

验收（N6b ✅，`NodeSolidTests` 的 `TestN6bCurves`）：矩形向外偏移 1 与偏移命令同为 22 × 12，直线 / 圆 / 圆弧偏移后类型不变，竖直平面内的空间曲线偏移后仍在该平面、
距离为 1；矩形倒 r 2 后周长 44 + 4π、半径过大保持尖角并警告、空间折线倒圆角长 16 + π；圆在两点处分成两个半圆弧、直线按 t 分段、椭圆被直线切成两段；
子曲线绕过圆与椭圆的接缝；直线两端延伸、圆弧沿圆延伸到 180°、圆弧末端接切线、抛物线自然延伸长度增加 2 与直线延伸的终点；
三条直线（一条反向）连成面积 50 的闭合多段线、直线 + 二次曲线、二次 + 三次经内核；矩形与倒圆角矩形炸开、空间圆角折线炸开成 3 段而椭圆不拆；
反转；投影到 XY 平面、直线投影到 z = 5 仍是直线、圆投影到球面上；圆重建为 12 个控制点（偏差 < 1%）、直线重建无偏差。

与原设计的差异（留待以后）：圆角只做一条曲线自身的拐角，不做两条曲线之间的圆角（可先连接）；偏移不处理结果的自相交（同偏移命令）；
分割、求交的切割曲线按采样求交，相切的交点可能漏掉；延伸不能为负（缩短用“子曲线”）。

## 5. 实体形体与空心（参考 Revit，N7）

### 5.1 五种形体

拉伸、融合、旋转有**工作平面**输入（`Plane`，默认世界 XY）——轮廓曲线按 XY 平面上的坐标解释、建好形体后整体放到工作平面上
（`Plane::ToWorld`，与 Revit 在工作平面上绘制轮廓相同），这样平面曲线节点不必关心三维位置。
放样、放样融合的轮廓放在路径起点处与路径垂直的平面上（轮廓的 Y 轴取最接近世界 +Z 的方向，即轮廓的“上”朝上），不需要工作平面。
实现在 `BuiltinFormNodes.cpp`：实心与空心共用 `SolveExtrude` 等求值函数。

| 形体 | 输入 | 参数 | 内核 |
|---|---|---|---|
| 拉伸 | 轮廓、终点（默认 10，旧版的“高度”）、起点（默认 0）、工作平面 | — | `Extrude(终点 − 起点)` 再沿 Z 平移起点；终点 < 起点时反向 |
| 融合 | 底部轮廓、顶部轮廓、高度（顶部轮廓相对底部的偏移）、工作平面 | — | `LoftSolid`（两截面、直纹、封口）；两轮廓统一为逆时针，各自从曲线起点对应 |
| 旋转 | 轮廓、轴点、轴方向、结束角度（默认 360，旧版的“角度”）、起始角度（默认 0）、工作平面 | — | `Revolve(结束 − 起始)` 再绕轴转起始角度；范围不超过 360°，轴不能穿过轮廓 |
| 放样 | 轮廓、路径（曲线或空间曲线）、轮廓角度 | 翻转 | 水平路径且不转不翻时用 `Sweep`（与旧版相同，折角斜接）；否则 `SweepAlong`（`SmApiCreateCurveSweep`），轮廓包围盒中心对准路径起点 |
| 放样融合 | 路径（空间曲线）、起点轮廓、终点轮廓、起点角度、终点角度 | — | `LoftSolid`：直线路径只取两端截面（精确）；曲线路径取 9 个站，中间截面由两轮廓按弧长各取 32 点线性过渡后插值，形体沿路径的弯曲是近似的 |

### 5.2 空心

- 五个空心节点与实心节点**共用求值函数**，只是输出的 `Value::Void = true`（`Value::VoidBody`），节点标题栏橙红色（“实体/空心”）。
  变换、阵列（`Geo::Transform`）、剪切几何、分割、抽壳保留输入的角色
- 空心本身是正常的封闭实体（体积、截面都能算），只是“角色”不同：预览为橙色线框、不烘焙
- `solid.role`（实心 / 空心）切换角色，相当于 Revit 形体属性里的“实心 / 空心”
- 并集 / 差集 / 交集**不区分角色**（按输入的位置运算），结果的角色取第一个输入的

### 5.3 空心切除

两种方式，对应 Revit 的两种行为：
- **形体合并**（`solid.combine`）：输入一个形体列表，`Union(全部实心)` 后依次 `Difference(每个空心)`。空心与实心不相交时忽略并警告“第 n 个空心没有切到实体”。
  这是“族里的空心自动切除族里的实心”的默认行为，大部分图只需要在最后放一个形体合并
- **剪切几何**（`solid.cut`）：“被切实体”（按项）+“切除体”（列表，实心或空心都可以），被切实体逐个减去全部切除体（没有切到的同样警告）。用于只切部分实体、
  或切图纸里引用的实体（`doc.bodies`；烘焙时生成新实体，不改原图实体——要替换原实体时烘焙后手动删除，或将来加“替换引用”的烘焙选项）

### 5.4 参数化控制

- **命名参数**（`input.param`，参数：名称、类别、值、公式）：名称在图内唯一，新建、复制、粘贴时自动编号（“参数1”“宽度2”）；
  名称必须能在公式里当变量用（不能是数值、函数名、常数，不能含运算符或空格）。类别决定输出类型：长度 / 角度 / 数值输出数值，整数取整，是否输出布尔。
  面板顶部“参数”按钮打开**参数表**（`MainFrame::OpenNodeParamsDialog`：名称、类别、值、公式，有公式的值只读并显示算出的值，出错的参数后面显示原因），
  “确定”后全部修改一步撤销；参数节点卡片上也能直接改
- **公式**：参数可以填公式（引用其他参数名，语法同 `math.expression`）；`math.expression` 也能直接用参数名（a～d 之外的变量）。
  实现：`Graph::Evaluate` 开头 `ResolveParameters()` 按公式依赖做深度优先求值（结果在 `Graph::Parameters()`，经 `SolveContext::Params` 交给节点），
  值或错误变了的参数节点、以及公式引用了变化参数的表达式节点标脏，再按拓扑顺序求值。成环时环上的参数都报“参数之间循环引用：a → b → a”，
  引用了出错参数的公式报“引用的参数有错误”，未知名称报“不是参数”，重名报“名称重复”
- **类型**（族类型，`ParamTypeDef`）：一组“参数名 → 值”。参数表里选择类型把值填进表格，“保存为类型”记下表格里的值（同名覆盖），“删除类型”；
  `Graph::SaveParamType` / `ApplyParamType`（只改没有公式的参数）/ `RemoveParamType`。类型随节点图保存（`nodeGraph.types`），撤销快照包含类型
- 滑块与参数的关系：滑块是“带范围的匿名参数”；参数节点设最小 / 最大值后显示为滑块（未做）

## 6. 曲面（参考 Grasshopper，N8）

- 输出仍是 `Body`（开放的 `BodyPtr`），与实体共用变换、预览、烘焙、读写、导出（第 4.4 节）
- **创建**的输入约定：截面 / 边 / 网络曲线一律用 `Curve3D` 端口（曲线实体自动转换）；需要方向一致的（放样、扫描、网络）在求值时统一曲线方向与接缝，
  并提供“对齐方向”参数（默认开）
- **拟合曲面**与**点阵曲面**的区别：点阵曲面要求规则网格点并经过各点；拟合曲面接受散乱点、按容差逼近（点阵曲面已有，拟合需要内核新接口）
- **参数曲面**：三个表达式在 u / v 区间上按采样数取点，再交给点阵曲面（插值）；不需要新的内核接口
- **修改**：修剪 / 分割的切割者可以是曲线（投影到曲面上）或曲面；拼接按容差缝合，结果封闭时 `IsSolid` 为真，下游就能做布尔；
  封口只补平面开口（非平面开口报错并提示用“边界曲面”补面再拼接）
- **分析**：分解输出的面是单面 `Body`、边是 `Curve3D`（`EdgeCurves`：边所在曲线转成 B 样条后按边的区间截取）、顶点是 `Vector`

实现在 `BuiltinSurfaceOps.cpp`（曲面的全部节点，注册顺序即菜单顺序；`BuiltinSurfaceNodes.cpp` 只剩“曲线/NURBS”），内核接口见第 10 节。

验收（N8 ✅，`NodeSolidTests` 的 `TestN8Surfaces`）：平面曲面带洞的面积 21π、挤出曲面面积 100π（开放）、三条直线的直纹放样、
单轨扫描（线段沿直线，面积 50）、双轨扫描（半圆截面沿两条平行直线得到半圆柱面 50π；轨道张开时截面随间距放大）、
边界曲面（四条边乱序、反向给出）与网络曲面（3 × 3 直线）都得到马鞍面 z = 0.1xy（中点 (5, 5, 2.5)）、拟合曲面经过散乱点、
参数曲面（圆柱方程）面积 100π；修剪（保留圆内 4π）、分割（两块面积之和 100）、长方体炸开 6 面后拼接回体积 1000 的实体、
管状曲面封口成圆柱（体积 250π）、翻转法线、延伸（10 × 10 → 12 × 12）、重建、修剪过的面拒绝翻转；
分解长方体（6 面、12 条精确边总长 120、8 个顶点）、等参线、线 × 面交点、球 × 平面交线（周长 8π）、球面曲率（|K| = 1/r²、|H| = 1/r、脐点）。

### 6.1 与原设计的差异（留待以后）
- 放样没有“松弛”类型；没有“对齐方向”参数（截面方向与接缝仍要用户保证，边界曲面的四条边会自动排序与定向）
- 单轨扫描只有一条截面；双轨扫描的截面最多两条，曲线轨道按 12 个截面放样近似
- 拟合曲面按控制点数逼近，不按容差；修剪 / 分割的切割者只能是曲线（沿方向投影），不能是曲面（可先“曲面求交”得到交线再修剪）
- 翻转、延伸、重建只用于没有修剪的单个面（按整张曲面计算）；带洞的修剪面的面积 `SmApiBrepComputeArea` 算不准（差约 3%，测试改用网格面积）

## 7. 几何运算与转换（N10 ✅）

### 7.1 运算

| 运算 | 节点 | 适用 |
|---|---|---|
| 布尔（并、差、交） | `solid.union` / `solid.difference` / `solid.intersection`、`solid.combine`、`solid.cut` | 封闭实体（开放曲面报错，提示加厚 / 封口）；网格先“网格转实体” |
| 分割 | `solid.split`（实体）、`surface.split`（曲面）、`curve.split`（曲线）、`mesh.split`（网格连通块） | 各自类型 |
| 修剪 | `surface.trim`、`curve.split` + 列表项 | |
| 拼接 / 连接 | `surface.join`（缝合曲面）、`curve.join`、`mesh.join` | 各自类型 |
| 封口 | `surface.cap` | 平面开口 |
| 加厚 | `surface.thicken` | 开放曲面 → 实体 |
| 求交 | `curve.intersect`、`surface.intersect`、`solid.section`、`mesh.section`、`mesh.intersect` | 见第 4.1 节归属规则；网格 × 任何几何都在“网格/分析” |

**求交的退路**（`MeshIntersect.cpp`，不依赖内核）：
- `surface.intersect` 加参数“方法”：**精确**（默认）由内核求交，内核没有结果而两者包围盒相交时，按细网格（`MeshOps::FromBodyFine`：角度 5°、
  弦高为包围盒对角线的千分之一）求交，有交线 / 交点就输出并警告“已改用网格近似”；**网格近似**直接按细网格求交（交线为折线，速度稳定）
- `solid.section`：内核没有截出结果而平面穿过实体包围盒时，同样退回细网格截面并警告
- 网格算法：截面按网格边编号连接截交点（正好在平面上的顶点按正侧处理，每条截交线只出现一次）；网格 × 网格用包围盒树找候选三角形对，
  三角形两两求交线段（交点按边端点的字典序计算，共边三角形得到完全相同的端点），再按容差连成折线（`ChainSegments`）；折线 × 网格用 Möller–Trumbore

**性能警告**：
- 实体面数超过 2000（`Geo::kManyFaces`，多由“网格转实体”得到）时，布尔、形体合并、剪切几何、曲面求交给出警告“有 n 个面……运算很慢（可先“简化”网格）”；
  “网格转实体”在面数超过 1 万时警告
- 卡片标题栏的求值耗时超过 1 秒时按秒显示并变为橙色；面板状态栏在最慢的节点超过 1 秒时显示“最慢：节点名 x 秒”

### 7.2 实体 / 曲面 / 网格 / 曲线之间的转换

| 从 \ 到 | 曲线 | 曲面 | 实体 | 网格 |
|---|---|---|---|---|
| **曲线** | 曲线实体 → 空间曲线（隐式） | 平面曲面、挤出曲面、旋转曲面、放样曲面、扫描、边界、网络 | 拉伸、融合、旋转、放样、放样融合、管道 | 闭合曲线网格 `mesh.fromcurve` |
| **曲面** | 分解（边）、等参线、曲面求交 | 偏移、修剪、分割、炸开 | 加厚、封口、拼接（封闭时） | 网格化（`Body` 连到 `Mesh` 端口时隐式） |
| **实体** | 分解（边）、截面 | 炸开、抽壳前的面 | — | 网格化（同上） |
| **网格** | ✅ N10：网格截面、网格边、网格轮廓线、网格求交 | 网格转实体（开放网格 → 多面曲面） | 网格转实体（封闭网格） | — |

转换的原则：
- **隐式转换只做无损或约定俗成的**：曲线实体 → 空间曲线（精确）、`Body` → `Mesh`（按默认精度，与 Grasshopper 相同）、平面 ↔ 点
- 有损或需要选择的转换都是显式节点（网格化的精度、网格转实体）
- 网格转实体得到的是多面实体（每个三角形一个平面面），布尔、加厚可用，但面数多、速度慢；节点在面数超过 1 万时警告，下游布尔在超过 2000 时警告
- 网格 → 曲线的结果都是一次空间曲线（折线）；水平的网格截面另外输出多段线（曲线实体，可以直接拉伸），与实体“截面”相同

## 8. 网格（N9）

- 数据：`Solid::Mesh`（顶点共用、面积加权的顶点法线、三角形索引，逆时针为正面）。只支持三角形；四边形在“构造网格”里自动拆成两个三角形
- 运算在 `src/NodeGraph/MeshOps.*`，**不依赖内核**（网页版可用）：长方体 / 经纬球 / 平面网格、构造、Delaunay 三角化（Bowyer–Watson，投影到平面）、
  带洞平面多边形的耳切三角化（洞经桥接边接到外圈）、焊接（空间哈希按容差合并顶点）、翻转、合并、连通块拆分、Loop 细分（边界按三次 B 样条规则）、
  Laplacian 平滑（可锁定边界）、边折叠简化（二次误差度量，边界边加大权重；会翻转三角形或破坏流形的折叠跳过）、仿射变换（镜像时三角形反向）、
  面积、体积、封闭判断、最近点
- 只有“网格化”（`Tessellate`）与“网格转实体”（新接口 `FromMesh`）依赖内核；实体 / 曲面连到网格端口时由 `Graph` 按默认精度网格化（没有内核时报错）
- `MeshEntity`（`src/Core/Entity/MeshEntity.hpp`）继承 `Solid3DEntity`：网格就是没有内核数据的“三维实体”，移动 / 旋转 / 镜像 / 缩放、夹点、捕捉、
  着色（两侧夹角小于 30° 的边按光滑处理）、轮廓线、导出多面网格都直接沿用；不同的是线框画全部网格边、导出时全部边可见，
  实体布尔与“引用实体”跳过它。`.mcad` / JSON 只存变换与网格（类型名 `MeshEntity`）；导入 DWG / DXF 的多面网格（POLYLINE，AcDbPolyFaceMesh）也映射到它
- 预览：网格 → `MeshEntity`（按网格缓存）进着色流；烘焙为 `MeshEntity`

验收（N9 ✅，`NodeSolidTests` 的 `TestN9Meshes`，前半部分不设内核）：网格长方体 8 顶点 12 面封闭体积 1000、每边 2 段时 26 顶点 48 面；
经纬球 266 顶点 528 面、体积略小于 4/3·πr³；平面网格 200 面面积 100；四边形构造；40 个伪随机点的 Delaunay 三角形数 = 2n − 2 − h 且朝平面法向；
20 × 10 矩形带 r 2 圆洞的闭合曲线网格面积 200 − 4π；两个长方体合并 16 顶点焊接回 8 个、平移后合并再拆分成 2 块；翻转后体积为负、镜像后仍为正；
细分面数 ×4 仍封闭、平滑（锁定边界的平面不变、球变小）、简化到 100 面以内仍封闭且体积误差 10% 以内；最近点、分解；
有内核时：长方体网格化封闭体积 1000、实体直接连网格端口、封闭网格转实体（体积 1000）与开放网格转曲面（面积 100）；
预览（没有内核也是着色的 `MeshEntity`）、烘焙（线框为全部网格边）、`.mcad` / JSON / DXF / DWG 往返三角形数与体积不变、一步撤销。

与原设计的差异（留待以后）：网格化没有“最大边长”（`TessParams` 没有这一项）；没有“显示网格线”开关（网格总是画全部边）；
网格转实体每个三角形一个面，不合并共面的三角形；简化、细分不保留纹理 / 顶点颜色（`Mesh` 没有这些数据）。

### 9.2 搜索过滤（✅ N5）

从**左侧输入引脚**拖出连接线到空白处时，搜索列表只显示能为这个输入提供数据的节点（有输出端口能转换到该输入的类型）；从右侧输出引脚拖出时对称处理。
逻辑在核心库：`NodeRegistry::SearchForPort` / `BestPort`、`MatchPorts`（`PortMatch`），编辑器的 `NodeSearchPopup` 只显示（`SearchRow`：类型、端口、说明）。

- **匹配等级**（每个候选取其最好的端口）：类型相同且 `Body` 子类型也相同（`Exact`）> 类型相同、子类型有一方不限，或几何接到 `Geometry` 输入（`Type`）>
  需要隐式转换或实体 / 曲面不符（`Convert`，如曲线实体 → 空间曲线、`Geometry` → 具体几何）> 只能经 `Any` / `Text` 端口接上（`Generic`）。
  `Geometry` 不算通用：拉伸的“轮廓”是 `Geometry`，算 `Generic` 时空关键词的列表是空的
  关键词为空时按“匹配等级 → 分类顺序表 → 注册顺序”排列（同一等级里同分类的节点相邻；没有做组标题）；有关键词时先按文字匹配度、同分再按匹配等级
- **排除**：只靠 `Any` 端口兼容的通用节点（列表、面板）不出现在空关键词的列表里（否则每次都排在前面），键入关键词后仍能搜到
- **自动连接的端口**：选中后连到匹配等级最高的端口（同级取第一个），而不是第一个兼容端口；例如从“加厚”的“曲面”输入拖出选“放样曲面”时连“曲面”输出
- **候选行**显示将要连接的端口（“→ 轮廓”“曲面 →”），隐式转换时带转换说明（“曲线 → 空间曲线”）
- **一致性**：添加节点菜单与搜索共用 `FitsPendingLink`（`BestPort` 非 `None`）：有待连接的引脚时只列出兼容节点，空的子菜单不显示
  （目前从引脚拖到空白处只打开搜索框；菜单的过滤为以后从引脚打开菜单预留）
- 测试（`NodeGraphTests`，过滤与排序逻辑放进核心库 `NodeRegistry::SearchForPort(query, type, kind, fromOutput)`，编辑器只负责显示）：
  从 `Curve3D` 输入拖出时候选里有“插值曲线”“直线”（隐式转换），没有“长方体”；从 `Body`（曲面）输入拖出时曲面节点排在实体节点前；
  从 `Number` 输出拖出时候选里没有只有几何输入的节点

### 9.3 引脚快捷断开（✅ N5）

- **Alt + 左键单击引脚**：断开这个引脚上的全部连线——输入引脚断开它的所有入线（`Graph::DisconnectInput`，恢复显示内联值），

- 搜索候选行里的分类显示为菜单路径（“实体 › 创建”），用户从搜索学到的位置就是菜单里的位置

## 12. 组节点（子图）（N11b ✅）

目标：把一组节点收成一个节点（Grasshopper 的 Cluster、Blender 的 Node Group），可以折叠复杂度、在图里多处复用、单独编辑。

### 12.1 数据模型
- **组定义** `GroupDef`：ID（文档内唯一，如 `group:3`）、名称、一张内部 `Graph`，以及**接口**：有序的输入端口与输出端口（名称、类型、访问方式、
  内联默认值）。接口端口在内部图里表示为两种特殊节点：`group.input`（只有输出端口，每个接口输入对应一个）与 `group.output`（只有输入端口）
- 组定义放在文档级的**组库**里（`Document::GetNodeGroups()`，随 `.mcad` / JSON 的 `nodeGraph.groups` 保存），一个定义可以被多个**组实例**节点引用
- 组实例是普通节点：`TypeId = "group:<定义 ID>"`。`NodeRegistry` 目前是全局只读的，组类型要按文档动态生成——
  `Graph` 增加一个“附加注册表”指针（文档的组库实现 `Find(id)`，查不到再查内置注册表），`NodeTypeInfo` 的端口由组接口生成，`Solve` 指向组求值
- 定义改了接口（增删端口）后，所有实例按端口**名称**重新对应（与读档时的类型升级同样处理：多余的连线丢弃、缺少的取默认值）

### 12.2 求值
- 组实例的 `Solve` 不按项迭代：所有输入端口按 `Access::List` 整列交给内部图（内部节点自己做最长列表匹配），
  把列表写进内部 `group.input` 的输出，求值内部图，再从 `group.output` 收集输出。每个实例持有自己的一份内部图副本（求值结果、脏标记互不干扰），
  定义改了时从定义重新复制
- 内部图沿用 `Graph::Evaluate` 的脏标记：实例的输入没变时内部不重算；内部有依赖图纸的节点时实例也标为 `DependsOnScene`
- 不允许递归（组 A 里含 A 的实例）：添加组实例、编辑定义时检查定义之间的引用关系是否成环
- 内部节点的错误汇总到实例上（“组内 2 个节点出错”），双击进入后看具体节点

### 12.3 编辑器
- **创建**：选中若干节点 → 右键“创建组”（Ctrl+G）。实现上复用剪贴板的子图：`CopyToString(选中)` 得到内部图；穿过选区边界的连线变成接口——
  从外部进入的连线各生成一个接口输入（同一个源端口只生成一个），从内部出去的生成接口输出；原节点删除，换成一个组实例并按接口重连外部连线。一步撤销
- **进入 / 返回**：双击组实例（或 Tab 键在选中组时）进入组内编辑，画布顶部显示路径（“主图 › 组名”），Esc / 路径按钮返回。
  组内编辑的是定义，返回时同步到所有实例；撤销历史仍是整个节点图的快照（快照里包含组库）
- **解组**：右键“解组”（Ctrl+Shift+G）把内部节点放回主图并恢复外部连线
- 组实例的卡片显示组名与接口端口，标题栏用单独的颜色；搜索框里可以按组名搜到当前文档的组，作为节点添加（菜单里放在最后的“组”大类）
- 复制粘贴：剪贴板子图里带上被引用的组定义，粘贴到另一张图纸时若组库里已有同 ID 但内容不同的定义，粘贴为新定义（改 ID）

### 12.4 预览与烘焙
- 预览只看组实例的输出（与普通节点相同）；进入组内编辑时预览组内的叶子输出与选中节点
- 烘焙不需要改动：组实例的输出就是普通几何

### 12.5 实现与上面设计的差异
- **组库属于顶层的图**（`Graph::Groups()`），不是 `Document::GetNodeGroups()`：顶层图的读写、撤销快照、剪贴板自然带上组库，
  存档位置仍是 `nodeGraph.groups`（被用到的定义写在前面，读入时嵌套的组类型已经存在）。组内的图共用顶层的组库
- **类型查找**：没有给注册表加“附加注册表”，`Graph::FindType` 按 `group:` 前缀到组库里找；组库用自己的 `NodeRegistry` 存实例类型
  （`NodeRegistry::Upsert` 就地更新，节点里的 `Type` 指针一直有效），菜单与搜索框把它的结果并进来
- **接口节点一个端口一个**：每个组输入 / 组输出是一个节点（参数“名称”），而不是一个多端口节点——可以用普通的节点卡片编辑，
  端口顺序按画布上从上到下（与 Grasshopper 的 Cluster 相同）。端口类型由组内连线推断：连到的端口类型都相同时取它，否则为任意；
  实例的输入都按列表访问、可选，没有数据时组输入输出自己的“默认”输入
- **组内编辑的是双击的那个实例的组内图**（有实际输入数据，预览也是真实结果），每次修改立即写回定义（`CommitGroupEdit`），
  其他实例按定义版本重建组内图；接口变了时全部实例（含嵌套在其他组内图里的）按端口名称重新对应。只挪位置时不触发重算
- **组定义随最后一个实例删除**（删除、剪切、解组时；撤销会连同定义恢复），菜单里的“组”只列出图里用到的组
- **组内的命名参数是组内自己的**：“参数”节点收进组后只在组内生效，组外的表达式引用不到
- **后台求值**：副本带着组库的深复制与要重算的实例的组内图；合并时实例的脏戳没变就整个采用副本里的组内图结果
  （`AdoptEvaluated`，对象不换，编辑器可能正显示着它）。组内有引用节点的组实例读图纸，与引用节点一样在界面线程上算
- **预览与烘焙**：组内图里只连到组输出的端口也算叶子输出（流向组输出的就是组的结果）；进入组内时“烘焙”烘焙组内图
- 未做：组内节点的错误不在主图里逐个标出（实例上显示“组内 N 个节点出错”）；组定义没有单独的管理界面（重命名在实例的右键菜单里）

## 13. 风险

- **SMLib 能力**：双轨扫描、网络曲面、拟合曲面、曲面修剪 / 拼接、抽壳、精确求交在 SMLib 里的支持程度未验证；每个接口先写冒烟测试，不支持的走第 10 节的退路或推迟
- **开放曲面的稳健性**：修剪、拼接容差不当会得到“几乎封闭”的多重曲面，`IsSolid` 为假导致下游布尔报错；拼接节点输出未缝合边的数量与位置（预览高亮）
- **融合 / 放样融合的顶点对应**：两轮廓段数、起点不同时容易扭曲；第一版用“顶点对应偏移”参数手动调，自动对齐按最近点
- **性能**：网格转实体、多空心切除在大列表上很慢；求值耗时显示在卡片上，超过阈值时警告；后台求值（N11）让界面不卡，但单个内核调用不能取消，“停止”要等当前调用结束
- **命名迁移**：显示名与分类调整会让老用户找不到节点——靠 `Keywords` 保留旧名，并在发布说明里列出改名表
