# 多段线逐段线宽（锥形段）：按 V0.1.0 的做法补回

用户报「多段线不同线段宽度不同的情况，需要修复」，并给出 `sample_AC1032.dwg` 的实例（句柄 `35B`）：

```
(0 . "LWPOLYLINE") (5 . "35B") (90 . 5) (70 . 0)
(10 12.1405 7.49932)  (40 . 0.2) (41 . 0.1)     ← 段 0：0.2 → 0.1
(10 10.9464 10.173)   (40 . 0.0) (41 . 0.0)
(10 12.7818 11.1673)  (40 . 0.0) (41 . 0.0)
(10 15.6845 8.91633)  (40 . 0.0) (41 . 0.0)
(10 13.2741 8.43021)  (40 . 0.1) (41 . 0.5)     ← 末顶点，开放多段线里没有「后一段」
```

对照 V0.1.0 的 `docs/修复记录.md` 第 **V8** 节（`## V8 多段线首尾宽度不一致`），
v0.2.0 里这条能力**整体缺失**，而且即使把数据补回来，还会被另一处阈值挡住（见 §3）。

## 1. 缺陷① 逐段宽度在导入时整批丢失

`PolylineEntity` 只有全局恒定宽度 `m_width`（DXF 组码 43）。`ConvertLwPolyline` 只读
`e.ConstantWidth`，每顶点 `v.StartWidth / v.EndWidth`（组码 40/41）被直接丢弃。

**实测 `sample_AC1032.dwg`**：23 条多段线里 2 条带 40/41（句柄 `35B`、`2E5`），
导入后场景里 `HasSegmentWidths()` 全是假 —— 宽度数据在往返中彻底消失。

**修法**：`PolylineEntity` 增加按段保存的 `m_segStartWidth / m_segEndWidth`，与 DXF 语义一致
（顶点 i 的宽度作用于「i → i+1」这一段）：

| 接口 | 作用 |
|---|---|
| `HasSegmentWidths()` | 是否存在任何非 0 的逐段宽度 |
| `SegmentStartWidth(seg)` / `SegmentEndWidth(seg)` | 该段的实际宽度；显式为 0 时**回退到恒定宽度**（DXF 的「0 = 用默认值」） |
| `SetSegmentWidths(startW, endW)` | 按段数补齐 / 截断后写入 |
| `SetSegmentWidth(seg, sw, ew)` / `ClearSegmentWidths()` | 单段写 / 整体清 |
| `MaxEffectiveWidth()` | 全段最大实际宽度（判「是否画带子」、扩包围盒都用它） |
| `SyncSegmentWidths()` | `SetPolyline` / `AddPoint` / `RemoveLastPoint` 后对齐到当前段数 |

数组按**段**对齐：开放段数 = 顶点数−1，闭合补重复末点后 = 顶点数（末顶点宽度落在闭合段上）。

## 2. 缺陷② 渲染只有恒定宽度一条路

`EmitThickPolyline` 只接受单个 `halfWidth`，每段都是等宽矩形。

**修法**：改为 `Node { P, hIn, hOut }` 节点序列 —— 折点处「到达段的半宽」与「离开段的半宽」
是两个独立值（正是首尾宽度不一致的来源）：

- 每段画成**梯形**（两端半宽相同则退化为矩形），两三角形拼接；
- 折点用**偏移边求交**的 miter 尖角（`P0 + s·d0 = P1 + t·d1` 解出交点 M）；
  半宽相等时等价于旧的 `miterLen = h/cosφ`；
- 斜接超过 8 倍半宽（接近反向折回）时退化为平接，避免无限尖刺；
- 圆弧段上的半宽按弧长线性插值。

恒宽多段线走同一条路径，几何与旧实现完全一致。

## 3. 缺陷③ 判据错：`宽度 >= 1.0` 把真实宽度挡在门外（本轮最要紧的一条）

即使前两条修好，**用户样例仍然画成细线**：旧判据是 `MaxEffectiveWidth() >= 1.0`，
而 `35B` 的段宽是 0.2 / 0.1 —— 数据保住了，画面上一模一样。

这个门槛来自「线宽」的旧近似（`Lineweight` 那种 1px 起算的屏显线宽），
但 LWPOLYLINE 的 40/41/43 是**实打实的模型单位宽度**：0.2 个模型单位就该画 0.2 个模型单位宽。

**修法**：新增 `DrawsAsBand()` —— 有逐段宽度时 `MaxEffectiveWidth() > 1e-9` 即画带子，
恒宽时 `m_width > 1e-9` 即画带子。恒宽默认值仍为 1.0，所以**新建多段线的外观不变**
（旧判据 `1.0 >= 1.0` 也走带子），`SetWidth(0)` 的仍是细线。

实测（`sample_AC1032.dwg` 句柄 `35B`）：

| | 三角形 | 结果 |
|---|---|---|
| 修前 | 0 | 细线，宽度看不见 |
| 只修 ①②（判据仍是 >= 1.0） | 0 | **仍是细线** |
| ③ 一并修 | **10** | 带子，半宽 0.1 |

## 4. 顺带补齐：粗多段线的虚线不再被画成实线

粗多段线整体填充成一条带子时**不经过线型解析**，虚线会被画成实线。
`IDrawSink` 增加两个默认实现（不破坏既有 sink）：

- `DrawStyledLine(a, b, color, width)`：按线型铺设有宽度的线段（默认退化为 `DrawLine`）；
- `IsCurrentLinetypeDashed()`：当前实体是否虚线（默认 false）。

`DrawContext` 在虚线时逐段调用 `DrawStyledLine`，连续线仍走整体填充（保留斜接尖角）；
`TransformDrawSink` / `ClipDrawSink` 转发时把宽度按插入缩放放大 / 按裁剪边界取舍。

## 5. 导出与序列化（否则另存即退化）

| 位置 | 改动 |
|---|---|
| `CadExchange.cpp` 导出 | `ConvertPolyline` 接收逐段宽度并写到顶点 40/41；有逐段宽度时不再写恒定宽度 43（两者同时存在会让顶点宽度被覆盖） |
| `CadExchange.cpp` 导入（旧式 POLYLINE） | 顶点 40/41 一并读入；顶点缺省时回退到 POLYLINE 自身的全局起止宽度 |
| `EntityIO.cpp` | `segStartWidths` / `segEndWidths` 仅在 `HasSegmentWidths()` 时写出，旧文件读出来是空数组 |
| `EntityScale.cpp` | 等比缩放时逐段宽度同步乘 k（宽度是长度量） |

## 6. 验证（全部为实测数字）

**新测试** `tests/Core/PolylineWidthTests.cpp`：12 项全过 —— 逐段宽度导入、段 0 为 0.2→0.1、
显式 0 回退恒定宽度、`MaxEffectiveWidth` 取逐段值、0.2 也走带子且半宽 0.1、
梯形两端半宽（4→1 时 ±2 收窄到 ±0.5）、等宽退化为矩形、DXF/DWG 两种往返保持 0.2→0.1、
恒宽 43 行为不变、宽度 0 仍走细线。

**真实图纸**（`sample_AC1032.dwg`，原图 = MiniDWG 读出的真值）：

| 项 | 原图 | 场景 |
|---|---|---|
| 带 40/41 的 LWPOLYLINE | 2 | 2（`35B` 段 0 = 0.2→0.1 ✔；`2E5` 见下） |
| 句柄 `35B` 渲染 | — | 带子，10 个三角形，半宽 0.1 |

`test0.dwg`（7680 条多段线）：带 40/41 的 **210 条**全部保住逐段宽度，MaxEffective 最大 450。

**`2E5` 的宽度在 AutoCAD 里本来就不生效**（不是缺陷）：它的两个宽度都在开放多段线的
**末顶点** v4（3.67 / 5.08），按 DXF 语义「顶点 i 的宽度作用于 i → i+1」，末顶点没有后一段。
本机参考实现（`WkViewer/reference/ocs_partial/OpenCADStudio-main/src/entities/polyline.rs`
的 `wide_fills`）也是这么取的：`for i in 0..seg_count { hw0 = v[i].start_width; hw1 = v[i].end_width; }`，
末顶点不参与。所以这里**不**把末顶点宽度挪给前一段。

**回归**：`MiniCADTests` 0 失败（含全部既有用例）、`MiniGUITests` 164 项 0 失败。
ctest 仍是那 3 项既有失败（`MiniCADCadPreserveTests` 的「Document open and save keeps Tianzheng objects」、
`MiniCADDrawingOpenTests` 0xC0000409、`MiniDWGTests` SEGFAULT），在未改动的 v0.2.0-sync 副本上同样复现。

## 7. 已知取舍

- **`PLINEGEN` 未处理**：闭合多段线的线型是否沿整条闭合环连续，目前按段各自起算。
- **宽度与线型叠加**：虚线走逐段 `DrawStyledLine`，折点处没有斜接尖角（与 V0.1.0 的取舍相同）。
- **`WIDTH_EPSILON`**：判定宽度是否为 0 用 1e-9，与参考实现的量级一致。
