# 对等的多窗口（桌面版）

> 状态：阶段 1 完成（2026-10-27）：文档窗口的标题栏换成 `MiniGUI::TitleBar`，能最小化 / 最大化，标题区域交给系统；
> 阶段 2 完成（2026-10-27）：一个窗口放几个文档，标签在任意窗口之间拖动合并；阶段 3 未开始。
> 前置（都已在 `dev`）：文档标签拖出成独立窗口；拖出时窗口实时跟随光标、文档窗口与主窗口平级（对话框不被挡住）、绘图区底色、
> 每个窗口一套绘图区界面（`MainFrame::ViewChrome`：视图方块、导航条、命令行、状态栏）。
> 定位：像 Chrome / VS Code 的多窗口，每个窗口都完整、可以放多个文档，标签在任意窗口之间拖动合并；停靠面板留在主窗口。
> 网页版、Linux 版给不出独立窗口（`AppPlatform::CreateFloatingWindow` 返回空），仍是单窗口，行为不变。

---

## 1. 目标

| | 主窗口 | 文档窗口 |
|---|---|---|
| 标题栏 | 图标、"文件"菜单、快速访问、文档标签、AI / 设置 / 帮助、最小化 / 最大化 / 关闭 | 同左（可以少 AI / 设置 / 帮助） |
| 功能区 | 有 | 有（同一份界面描述、同一套命令） |
| 绘图区界面 | 视图方块、导航条、命令行、动态输入 | 同左 |
| 状态栏 | 模型 / 布局标签、捕捉等开关、读写进度、界面描述加载结果 | 模型 / 布局标签、捕捉等开关 |
| 停靠面板 | 特性、图层、节点（跟着当前文档） | 无 |
| 没有文档时 | 起始页 | 窗口关闭 |
| 关闭 | 退出程序（逐个询问未保存的文档） | 关闭它里面的文档（逐个询问未保存的） |

- 标签拖动（同 Chrome）：任何窗口的标签拖出标签条就成为新窗口，拖动中窗口跟着光标；拖到任何窗口的标签条上，画插入标记，松开即合并进那个窗口；
  窗口里只有一个标签时，拖这个标签就是拖整个窗口；窗口里最后一个文档被拖走后窗口关闭
- 拖动标题栏交给系统：双击最大化、拖到屏幕边缘贴边分屏（Aero Snap）；拖到别的窗口的标签条上松开也合并
- "当前文档"仍是一个（`DocumentManager::GetActive`），随用户最后操作的窗口切换；面板、菜单与功能区的命令作用于它

## 2. 要改的结构

1. **文档管理**（阶段 2 已改成窗格模型）：原来是"主视口 + 每个拖出的文档一个视口"（`DocumentManager::DetachDocument` / `DocumentManager::AttachDocument`，现在是窗格操作的简便写法），
   一个独立窗口只能放一个文档。改成"每个窗口一个视口（窗格），窗格里的多个文档轮流用它，切换时保存 / 恢复各自的相机"——
   主视口现在就是这样做的（`DocumentManager::SetMainDocument`），主窗口成为 0 号窗格
2. **窗口**：`MainFrame` 里主窗口与文档窗口是两套建法（主窗口经界面描述，文档窗口在 `MainFrame::FloatDocument` 里手搭）。
   改成同一种窗口结构：标题栏、功能区、绘图区界面、状态栏都由界面描述生成，主窗口只是多了停靠面板与起始页
3. **只能有一份的部件**：
   - `MiniGUI::TitleBar` 的三个按钮走全局命令（`window.minimize` / `window.maximize` / `window.close`），只能作用于主窗口——要能按窗口指定动作
   - 功能区里的图层 / 线型 / 线宽下拉框是宿主面板 `layerbar`（`MainFrame::CreateLayerBar`），只建了一份——要每个窗口一份
   - 快捷键只登记在主窗口的 `UIContext` 上，文档窗口靠把没处理的按键转给主窗口（`Win32Window::ForwardKeyMessage`）——要每个窗口一份

## 3. 分阶段

每个阶段单独编译、测试、提交；做完一段就能用上一段。

### 阶段 1：窗口框架（小）——已完成（2026-10-27）

做法与计划的出入：标题栏按钮的动作用 `MiniGUI::TitleBar::SetWindowActions`（不设置时仍走 `window.*` 命令）；
`IFloatingWindow` 加了 `Minimize` / `ToggleMaximize` / `IsWindowMaximized`（不叫 `IsMaximized`：windowsx.h 有同名宏）、
`SetCaptionTest`、`SetOnActiveChanged`（窗口激活时它的文档成为当前文档）、`SetOnSizeChanged`、`SetOnMoving`；
双击标题栏现在是最大化（原来是合并回主窗口），合并回去靠拖到标签条上。自测第 29 节：标题区域命中、最大化 / 还原 / 最小化、激活、
系统移动循环拖回标签条（发 `WM_ENTERSIZEMOVE` / `WM_MOVING` / `WM_EXITSIZEMOVE` 模拟，不动真实光标）。真实鼠标拖动未实测。

- 文档窗口的标题栏换成 `MiniGUI::TitleBar`：左边先显示文档名（阶段 2 换成标签条），右边最小化 / 最大化 / 关闭；
  标题栏按钮改为可以按窗口指定动作（不指定时仍走全局命令，主窗口不变）
- `Win32FloatingWindow` 的文档窗口加上最小化 / 最大化框，标题区域交给系统（`MiniGUI::Win32Frame` 的标题命中测试，同主窗口）：
  系统拖动、双击最大化、贴边分屏；最大化时不盖住任务栏
- 拖动标题栏改走系统的移动循环：移动中检测光标是否在某个窗口的标签条上（画插入标记），结束时在标签条上就合并——
  取代现在 `MiniGUI::FloatingPanel` 自己拖窗口的做法；标签刚拖出、鼠标还没松开时仍由标签条转来移动（`MiniGUI::TabView::SetOnTornTabDrag`）
- 验收：文档窗口能最小化 / 最大化 / 贴边；拖标题栏回主窗口的标签条照常合并；自测第 29 节相应改写

### 阶段 2：一个窗口多个文档，标签在任意窗口之间拖动（核心，最大）——已完成（2026-10-27）

做法与计划的出入：
- 窗格：`DocumentManager::CreatePane` / `DocumentManager::MoveDocument` / `DocumentManager::GetShownDocument` / `DocumentManager::PaneOf`，窗格里的文档都移走后自动删掉，界面在 `MainFrame::SyncDocuments` 里关掉对应的窗口；`DocumentManager::SetActive` 让文档成为它所在窗格显示的文档，顺带把新建 / 打开的文档放进这个窗格（`DocumentManager::SetNewDocumentPane`）
- 主窗口没有文档而别的窗口有：**不显示起始页**（起始页会盖住面板，面板还要给别的窗口用），绘图区中间显示提示卡片（新建 / 打开），命令行、视图方块、导航条不显示；一个文档都没有时才是起始页
- 落点放宽到窗口的整个标题栏那一行（标签左边插到最前、右边的空白处接到最后），不必正好落在标签上
- 被拖的窗口挡住落点：没有做 Chrome 那样"窗口收起、标签插进标签条继续拖"，而是光标在别的窗口的标题栏上时让被拖的窗口挪到那条标签条下面（标签拖出时在 `MainFrame::DragDocWindow` 里挪，系统的移动循环在 `IFloatingWindow::SetOnMoving` 的回调里改窗口位置）
- 自测第 30 节（20 项）：拖到别的窗口的标签条、窗口里切换、新建进当前窗口、从文档窗口拖回、只有一个标签的窗口拖标签即拖窗口、拖标题栏合并全部文档、窗口让开标签条、主窗口空着、关闭窗口关掉里面的文档；`tests/Core/DocumentViewportTests.cpp` 补窗格的用例
- 没做：`--bench` 只测主窗口，两个窗口同时显示大图纸的帧耗时还没测（见第 5 节）；真实鼠标拖动未实测

- 文档管理改成窗格模型：建 / 删窗格、把文档移到某个窗格的某个位置、窗格当前显示哪个文档、文档在哪个窗格；
  编辑器绑定到它所在窗格的视口。`tests/Core/DocumentViewportTests.cpp` 补多文档窗格的用例（移动、切换、相机保存、关闭）
- `MainFrame` 的文档窗口改成通用的窗口（主窗口也是一个），每个窗口有自己的文档标签条，`MainFrame::SyncDocuments` 逐窗口同步；
  每个窗口一套的绘图区界面（`MainFrame::ViewChrome`）并进窗口
- 拖动：任何窗口的标签都能拖出成新窗口、拖到任何窗口的标签条上合并（落点在各窗口的标签条里找，按屏幕坐标）；
  只有一个标签的窗口拖标签即拖窗口；窗口空了就关闭
- 关闭：文档窗口的 × 关闭它的文档（逐个询问）；主窗口的 × 退出程序
- 主窗口没有文档时显示起始页
- 验收：两个窗口各放两张图，标签互相拖动、合并、拖出；各窗口独立切换文档；单元测试与自测覆盖；
  用 `--bench` 对比两个窗口同时显示大图纸时的帧耗时（见第 5 节）

### 阶段 3：每个窗口的功能区与标题栏工具（中）

- `assets/ui/minicad_ui.json` 新增"文档窗口布局"一段：标题栏（"文件"菜单、快速访问、文档标签、窗口按钮）、功能区、绘图区界面、状态栏，没有停靠区；
  每个窗口用自己的 `MiniGUI::UiLayout` 按它生成，命令表共用
- 图层 / 线型 / 线宽下拉框改成每个窗口一份，显示那个窗口里文档的状态，改动作用于它
- 每个窗口登记自己的快捷键；去掉文档窗口把按键转给主窗口的做法（文档窗口内容节点上的收尾、`Win32Window::ForwardKeyMessage` 对文档窗口不再需要）
- 界面描述文件改了自动重新加载、切换主题：所有窗口一起
- 验收：在副屏的文档窗口里只用它自己的功能区、快捷键完成画图、修改、保存

### 阶段 4：收尾（小到中）

- 动态输入框（光标旁的长度 / 角度）每个窗口一份（现在只在主视口里显示）
- 可选：对话框开在当前操作的窗口里（约 13 处调用 `m_ui->OpenPopup` / `ShowContextMenu(*m_ui, …)`）；
  不做时保留"弹对话框时把主窗口置前"（`MainFrame::RaiseMainForModal`）
- 文档：`.agents/features/main-window.md`、`docs/MiniGUI/PLAN.md`（标题栏按钮按窗口指定动作、标签跨窗口拖放）
- 自测第 29 节改成多窗口的完整流程：拖出、合并、窗口之间移动、最大化 / 最小化、关闭

## 4. 不做 / 不变

- 网页版、Linux 版：单窗口
- 停靠面板只在主窗口，跟着当前文档；浮出的面板仍是主窗口拥有的工具窗口
- 用户布局文件不保存文档窗口：下次启动所有文档都在主窗口里
- 不做：窗口之间拖动实体（跨文档复制粘贴照常经剪贴板）

## 5. 风险与待定

- **渲染器顶点缓冲**：每个槽位只留一份，几个视口轮流画会互相顶掉，靠 `Editor::EnsureSceneCached` 从逐实体缓存重新拼接。
  几个窗口同时显示大图纸、同一时间都在重画时每帧都要重新拼接，可能变慢；阶段 2 做完用 `--bench` 测，需要时按视口分槽位
- **系统移动循环里画落点**：Windows 的标题栏拖动是模态的移动循环，主窗口照常收到重绘消息，但要确认落点标记能及时画出来。
  阶段 1 发现：光标按在被拖窗口的标题栏上，标签条上光标附近正好被这个窗口自己盖住，插入标记常常看不见（松开照样合并）。
  阶段 2 的处理：光标在别的窗口的标题栏上时，被拖的窗口挪到那条标签条下面（不是 Chrome 的"收起窗口、标签插进去继续拖"）
- **最大化的无边框窗口**：`MiniGUI::Win32Frame` 主窗口已处理（不盖住任务栏、留出边框），文档窗口复用同一套
