# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

MiniCAD is a cross-platform 2D CAD editor written in modern C++ (C++20). One repository holds three libraries plus the apps: the platform-independent core library MiniCADLib, the retained-mode GUI library MiniGUI, and the DWG/DXF library MiniDWG. Platforms: Windows (DirectX 11) and web (Emscripten/WebGL2) — both draw the same MiniGUI interface from the same code (`apps/Common`). The repository was formed in 2026-10 by merging the former MiniCADLib, MiniGUI and MiniDWG repositories (history not kept; the old repos are archived on GitHub).

**Layout:**
- `src/`: Core library (target `MiniCADLib`, namespace `MiniCAD`)
- `src/UI/`: MiniGUI retained-mode GUI library (targets `MiniGUI`, `MiniGUI_Win32`, defined in `cmake/MiniGUI.cmake`; namespace `MiniGUI`). Platform layers: `src/UI/Platform/Win32` (`MiniGUI_Win32`) and `src/UI/Platform/Web` (`MiniGUI_Web`: DOM input, IME via a hidden textarea, clipboard, bundled UI font). Plan/milestones: `docs/MiniGUI/PLAN.md`
- `src/Serialization/Codec|Database|Dwg|Dxf/`: MiniDWG DWG/DXF read/write library (port of ACadSharp, MIT; target `MiniDWG`, defined in `cmake/MiniDWG.cmake`; namespace `MiniDWG`). Linked `PRIVATE` into MiniCADLib (also in the WASM build), so MiniCADLib public headers must not expose MiniDWG types. It stays independent of MiniCADLib; mapping `MiniDWG::CadDatabase` ↔ `Scene` belongs in `src/Import/`. Plan/milestones: `docs/MiniDWG/PLAN.md`; `*.g.cpp` are generated by scripts in the archived MiniDWG repo's `tools/`
- `apps/Common/`: the main window's UI and logic shared by desktop and web (target `MiniCADApp`: `MainFrame`, commands, panels, command line, dialogs). Platform services come through the `AppPlatform` interface (`apps/Common/src/GUI/AppPlatform.h`)
- `apps/Win32/`: desktop host `Win32Window` (borderless window, D3D11, message loop; implements `AppPlatform`), `--selftest` (`Host/SelfTest.cpp`). `apps/Win32/src/Render/` holds the CAD renderer `D3D11Renderer` and MiniGUI's backends (`D3D11/D3D11Backend` → `MiniGUI_D3D11`, `Software/SoftwareBackend` → `MiniGUI_Software`)
- `apps/Web/`: web host `WebApp` (canvas + WebGL2 via `WebHost`, browser file picker / download; implements `AppPlatform`), target `MiniCADWeb`. `apps/Web/src/Render/` holds the CAD renderer `GLES3Renderer` + `GLRenderTarget` and MiniGUI's `WebGL2/WebGL2Backend` (`MiniGUI_WebGL2`). `MiniGUIWebGallery` is a MiniGUI widget demo for the browser
- `wasm/`: legacy C-API WASM target for an HTML/JS front end (not in the repo); only built with `-DMINICAD_BUILD_LEGACY_WASM=ON`, which also defines `MINICAD_WEB` for MiniCADLib (JS hooks for text input, auto block names, texture-atlas text) and excludes `apps/Web`
- `tools/make_web_font.py`: regenerates `assets/fonts/NotoSansSC-UI.ttf` (web UI font, Noto Sans SC Regular subset, OFL)
- `tests/`: `Core/` (MiniCADLib), `UI/` + `UI/Golden/` (MiniGUI), `Serialization/` (MiniDWG), `Data/` (DWG/DXF samples, golden-test icons)
- `3rd/`: Third-party dependencies (stb_image, stb_truetype), shared by MiniCADLib and MiniGUI
- `docs/`: tutorials/articles from the earlier MiniCAD project (describe an older architecture) plus library plans

**Include roots (important):** each library has its own include root — MiniCADLib → `src`, MiniGUI → `src/UI`, MiniDWG → `src/Serialization`, shared app → `apps/Common/src`, Win32 app → `apps/Win32/src` and `apps/Win32/src/Render`, web app → `apps/Web/src` and `apps/Web/src/Render`. `src` and `src/UI` both contain `Core/`, `Render/`, `Text/`; currently no relative path (`Core/Foo.h`) exists under two roots. Keep it that way — a duplicate would silently resolve to whichever root comes first. Namespaces stay `MiniCAD` / `MiniGUI` / `MiniDWG`.

## Architecture Overview

### Core Systems

**Entity System** (`src/Core/Entity/`)
- All drawable objects inherit from `Entity` which extends `Object` (base class with ID management)
- 27+ entity types: `LineEntity`, `CircleEntity`, `ArcEntity`, `TextEntity`, `DimensionEntity`, `BlockEntity`, etc.
- Entities support: cloning, bounding boxes, drawing to render sink, serialization
- `ICurveEntity` interface for geometric operations (used by snapping, intersection, editing)

**Scene Graph** (`src/Scene/`)
- `Scene`: Container for all entities, manages layers, line types, blocks, current entity attributes
- `LayerManager`: Layer hierarchy and visibility control
- `BlockTable`: Block definitions (reusable entity groups via `InsertEntity`)
- `LineTypeTable`: Line style definitions; `DimStyleTable`: dimension style definitions
- Dirty flag + geometry version tracking for invalidating spatial indices

**Document & Undo/Redo** (`src/Document/`)
- `Document`: Wraps scene, provides save/load, undo/redo, document metadata (name, path)
- `CommandStack`: Undo/redo via command pattern; all edits must go through `ICommand` subclasses
- Commands live in `src/Document/Command/`: `AddEntityCommand`, `BatchDeleteCommand`, `EntityTranslate`, `MoveCommand`, `CopyCommand`, `RotateMoveCommand`, etc.

**Editor** (`src/Editor/`)
- Input pipeline: `InputResolver` → `Editor` → tools/constraints
- Tools system (`src/Editor/Tools/`): Abstract `ITool`; draw tools like `LineTool`, `PolylineTool`, `CircleTool`; modify tools in `Tools/Modify/` (`MoveTool`, `TrimTool`, `OffsetTool`, etc.)
- Picking: Ray-based entity selection with spatial acceleration
- Snapping: `SnapEngine` with results for endpoints, midpoints, centers, intersections, etc.
- Grips: `GripEditor` for interactive geometry manipulation
- Constraints: Orthogonal, polar angle snapping

**Rendering** (`src/Viewport/` + platform-specific)
- `Viewport`: Manages camera, collects vertices, batches render calls
- `ViewState`: Position, zoom, selection, hover state
- Draw sink interface: Platform-independent drawing API (lines, circles, text, etc.)
- Renderers implement `IRenderer`: `D3D11Renderer` (Win32), `GLES3Renderer` (web). GL texture/framebuffer handles are passed by value inside the `void*` (see `GLRenderTarget`)

**Serialization** (`src/Serialization/`)
- `ISerializer`: Abstract interface for format-agnostic serialization
- `JsonSerializer`, `BinarySerializer`: Format implementations
- `EntityIO`: Entity-to-serializable data mapping

**DWG/DXF 交换** (`src/Import/CadExchange.*`)
- `ImportCad` / `ExportCad` 经 MiniDWG 的 `CadDatabase` 与 `Scene` 互转；`Document::LoadFromFile` / `SaveToFile` 按扩展名 `.dwg` / `.dxf` 分派（导出固定 R2018，DXF 为 ASCII）
- 已映射：图层、线型、文字样式、块、Line/Circle/Arc/Ellipse/Point/Polyline/Text/MText/Insert；标注导入时用其匿名块还原为 Insert；其余实体（Hatch、Spline、Leader、Solid 等）跳过并 `LOG_WARN`
- 测试：`tests/Core/CadExchangeTests.cpp`（往返 + MiniDWG 样例图）

**Text & Fonts** (`src/Text/`)
- `FontEngine`: Manages SHX (shape) fonts and TTF fonts
- `TextLayoutEngine`: Text measurement and layout
- GBK encoding support for CJK characters

### Geometry Kernel (`src/Core/GeomKernel/`)
- Primitive shapes: `Point3`, `Line`, `Circle`, `Arc`, `AABB`
- Curve abstraction: `ICurve` interface with implementations (`LineCurve`, `CircleCurve`, etc.)
- Intersection algorithms: `CurveIntersect` for snapping and geometry operations
- Math utilities: Vectors, matrices, transformations

## Build & Development

### Build with CMake

Use CMake presets defined in `CMakePresets.json`:

```powershell
# Configure (first time)
cmake --preset debug

# Build
cmake --build out/debug --config Debug

# Or via preset
cmake --build --preset debug
```

**Presets available:**
- `debug`: Debug build with Ninja generator, output to `out/debug/`
- `release`: Release build with Ninja generator, output to `out/release/`

**Build environment gotcha:** Running `cmake --build` from a plain PowerShell/cmd shell fails with `fatal error C1083: Cannot open include file: "cmath"` (or `vector`). The cached `cl.exe` path is valid, but MSVC's standard-library `INCLUDE`/`LIB` paths come from the developer-environment variables, which a plain shell lacks. Wrap the build in `vcvars64`:

```powershell
cmd /c "\"C:\Program Files\Microsoft Visual Studio\18\Community\VC\Auxiliary\Build\vcvars64.bat\" >nul 2>&1 && cmake --build out/debug --config Debug"
```

Adjust the VS install path as needed. Building from a "Developer PowerShell/Command Prompt for VS" or from within Visual Studio avoids this.

Verify changes by building, running the tests (`run_tests.bat`, see Tests below) and running the Win32 app.

**Requirements:**
- CMake 3.20+
- C++20 compiler (MSVC for Win32, Emscripten for Web)
- Ninja build tool
- DirectX 11 SDK (for Win32 app)

### Run the Windows App

After building, the executable is at `out/debug/MiniCADWin/MiniCADWin.exe` (or `out/release/...` for Release).

Double-click to run, or debug via Visual Studio with the `.vs/` solution.

### Web Build (WASM)

```powershell
build_wasm.bat
```

Release build of the web app (target `MiniCADWeb`, plus `MiniGUIWebGallery`) into `out/build/wasm/`; open `out/build/wasm/MiniCADWeb/index.html` through a local HTTP server (`build_wasm.bat serve` starts one on port 8080; `file://` does not work). `build_wasm.bat configure` reconfigures from scratch. The script expects emsdk at `D:\dev\emsdk` and looks for Ninja in the Visual Studio install — edit the top of the script if the toolchain moves. Assets are preloaded into the virtual file system root (`/fonts`, `/icons`, `/patterns`, `/ui`); browser keyboard events are mapped through `KeyboardEvent.keyCode`, text and IME arrive through a hidden textarea that follows the text caret.

## Key Design Patterns & Conventions

### Object Identity & Ownership

- All entities have unique `ObjectID` (uint64_t); ID 0 is reserved (`InvalidID`)
- Entities are owned by `Scene` (stored in `m_entities` map)
- Undo/redo works by removing/restoring ownership (see `RemoveEntity()`, which returns unique_ptr)
- No circular ownership; use raw pointers for back-references (safe because Scene owns the lifetime)

### Command Pattern for Edits

All modifications must create an `ICommand` subclass:
1. Implement `bool Execute(Scene&)` and `void Undo(Scene&)` — `Execute()` returning false means failure; the command is not pushed onto the undo stack
2. Push to `Document::GetCommandStack()` after execution
3. Example: `MoveCommand` stores before/after positions; `Execute()` moves, `Undo()` restores

**Important:** Direct mutation of entities bypasses undo, use commands instead.

### Entity Attributes

`EntityAttr` (color, layer, line type, lineweight) are inherited from layer defaults (`ByLayer`). Changing current attributes via `Scene::SetCurrentLineType()` affects new entities only.

### Geometry Version Tracking

`Scene::m_geomVersion` increments on any topological/geometric change. Used by spatial indices (picking) to invalidate caches without expensive scene rescans. Touch it when adding/deleting/moving entities.

### Serialization Contract

`ISerializer` interface is used for both JSON and binary. Each entity type registers its serialization via `DECLARE_RUNTIME_TYPE` macro. On deserialization:
1. Blocks and line types are resolved first (dependencies)
2. `ResolveAllInserts()` must be called to parse block references
3. See `src/Serialization/EntityIO.cpp` for entity-to-data mapping

### App Integration (desktop and web)

The whole UI is drawn by MiniGUI (`src/UI`); the UI is rendered by the MiniGUI backend (`D3D11Backend` / `WebGL2Backend`), a different thing from the CAD-viewport renderer (`D3D11Renderer` / `GLES3Renderer`). Shared code in `apps/Common/src/GUI` must stay platform-free — anything platform-specific goes through `AppPlatform` (graphics objects, redraw scheduling, window title/buttons, file picking that may be asynchronous, save-path choice + `OnDocumentSaved`, resource and user-data directories):
- `GUI/MainFrame`: document tabs, viewport input → `Editor`, frame rendering (`RenderFrame`), resize (`OnResize`); hosts call these. `RunSelfTest` is defined only in the Win32 app
- `Host/Win32Window` (Win32): borderless window (`MiniGUI::Win32Frame`), D3D11 device/swap chain, message loop, UI-file watching. `Host/WebApp` (web): `WebHost` canvas/WebGL2/DPI/requestAnimationFrame, `/upload` + download for files, `beforeunload` guard; no window buttons (the `window.*` commands are not registered, so the title bar hides them)
- `GUI/MainCommands.cpp`: all operations registered as MiniGUI commands; menus/toolbars/dock layout come from `assets/ui/minicad_ui.json` (hot-reloaded)
- `GUI/MainPanels.cpp`, `LayerPanels.cpp`, `CommandLine.cpp`, `DynamicInput.cpp`, `EditorDialogs.cpp`, `StatusBarView`: properties/layers panels, command line, dynamic input, text/block/array dialogs, status bar
- `D3D11Renderer`: executes draw sink commands into the viewport render target, shown by `MiniGUI::ViewportHost`

Input flows: Win32 / DOM → `MiniGUI::Win32Input` / `MiniGUI::WebInput` → `UIContext` → `ViewportHost` → `MainFrame::OnViewportPointer/Key` → `Editor::OnInput`, in the same frame. UI dialogs are driven by Editor "requests" (`GetTextInputRequest`, `GetArrayRequest`, ...).

### Debug & Logging

`Core/Log.h` provides `LOG_INFO`, `LOG_WARN`, `LOG_ERROR` macros. Used throughout for debugging entity operations, serialization, rendering.

## Common Tasks

### Tests

- `run_tests.bat [debug|release]` — builds and runs everything through ctest. Test programs are written to `out/<preset>/`, defined in `tests/CMakeLists.txt`.
- `MiniCADTests.exe` — core library tests (`tests/Core/`: spatial index, entities, commands, DWG/DXF exchange …). Exit code = number of failures.
- `MiniGUITests.exe` — MiniGUI unit tests (`tests/UI/`).
- `MiniGUIGolden.exe` — MiniGUI screenshot tests: software rasterizer vs `tests/UI/Golden/baseline`, D3D11 vs software. Update baselines with `MiniGUIGolden.exe --update`, review the images before committing. As of the merge (2026-10-08) 10 baseline scenes (titlebar/dock/documents) already failed in the original MiniGUI repo too.
- `MiniDWGTests.exe` — MiniDWG tests (`tests/Serialization/`, samples in `tests/Data/Dwg/`).
- `out/<preset>/MiniCADWin/MiniCADWin.exe --selftest` — end-to-end UI selftest (injected window messages) plus frame-timing and large-drawing measurements.
- Dirty flags: use `Scene::MarkEntityDirty(id)` for single-entity edits, `Scene::MarkDisplayDirty()` for display-only global changes (layer color/visibility/linetype), and `Scene::MarkDirty()` only when geometry changes globally — it forces a full rebuild of the picking spatial index.

### Add a New Entity Type

1. Create header in `src/Core/Entity/NewEntity.hpp` (inherit from `Entity`, optionally `ICurveEntity`)
2. Define geometry member and accessor
3. Implement `Clone()`, `GetBoundingBox()`, `Draw()`
4. Add `DECLARE_RUNTIME_TYPE` macro
5. Register in `EntityIO.cpp` serialization
6. (Optional) Add tool in `src/Editor/Tools/` to create instances

### Add a New Tool

1. Create `src/Editor/Tools/MyTool.h` inheriting from `ITool`
2. Implement `OnEnter()`, `OnInput()`, `OnExit()`, `Render()` virtual methods
3. Input handling: use `InputResolver` for coordinate snapping, `SnapEngine` for visual feedback
4. Commands: create and push via `m_cmdStack->Push()`
5. Register the tool as a command in `apps/Common/src/GUI/MainCommands.cpp` (tool table) and place it in `assets/ui/minicad_ui.json`

### Modify Entity Geometry

All edits must go through commands. Example:
```cpp
auto cmd = std::make_unique<EntityTranslate>(selected_id, delta);
cmd->Execute(scene);
doc.GetCommandStack().Push(std::move(cmd));
```

### Work with Layers

```cpp
auto& layers = doc.GetLayerManager();
layers.CreateLayer("NewLayer");
layers.SetCurrentLayer("NewLayer");
// New entities will be on current layer by default
```

### Serialization

Save/load via `Document::SaveAs()` / `LoadFromFile()`. Format is selected by file extension: `.mcad` (case-insensitive) → binary, anything else (`.json`, etc.) → JSON text. Both formats carry equivalent content.

## File Organization Notes

- Headers in `src/*/` mirror the source structure; use `#include "Module/File.h"` relative to `src/`
- Library sources are listed explicitly (no globbing) — MiniCADLib in the top-level `CMakeLists.txt`, MiniGUI in `cmake/MiniGUI.cmake`, MiniDWG in `cmake/MiniDWG.cmake`, shared app in `apps/Common/CMakeLists.txt`, Win32 / web hosts in `apps/Win32/CMakeLists.txt` / `apps/Web/CMakeLists.txt`, tests in `tests/CMakeLists.txt`; adding a new `.cpp` requires adding it there. Entity types are header-only (`.hpp`), so new entities usually need no CMake change.
- `src/Core/Object/Object.hpp`: Base class for all scene objects (type info, ID)
- `src/Core/GeomKernel/`: Primitive geometry, no entity-level logic
- `src/Editor/`: Input-driven editing, decoupled from rendering
- `src/Render/VertexTypes.hpp`: Draw sink command format (platform-independent)

## Performance Considerations

- Spatial indices (in picking) are cached and invalidated via `Scene::GeometryVersion()`
- Large scenes: consider entity pooling or spatial partitioning
- Drawing: batch similar render calls (color, line weight) for fewer sink calls
- Snapping: `SnapEngine` is O(n) per frame; optimize with spatial index if needed
